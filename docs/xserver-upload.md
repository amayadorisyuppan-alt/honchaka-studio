# Xserver への公開手順

このアプリは完全な静的サイトとしてビルドされるため、Xserver にはビルド成果物をアップロードするだけで公開できます。サーバー側の設定変更・PHP・データベースは不要です。

## 1. ビルド

```bash
npm run build
```

`dist/` フォルダに公開用ファイル一式が生成されます(相対パス設定済みのため、どのサブディレクトリに置いても動きます)。

## 2. アップロード

1. Xserver のファイルマネージャ(または FTP)を開く
2. 公開したい場所にフォルダを作る(例: `hittyaka-maker.com/public_html/bookstudio/`。公開 URL は `https://www.hittyaka-maker.com/bookstudio/`)
3. `dist/` の**中身をすべて**そのフォルダにアップロードする

**「すべて」が肝心。** 内訳は以下のとおりで、どれか1つでも欠けると機能が黙って死にます
(実測 2026-08-17: 合計 約99MB / 3,197ファイル)。

| | 大きさ | 中身 | 欠けるとどうなるか |
|---|---|---|---|
| `index.html` | 4KB | 入口 | — |
| `assets/` | **84MB** | JS・CSS と**書体3,086ファイル**(woff2) | 日本語が閲覧環境の書体に落ちる |
| `covers/` | 15MB | 表紙プリセット45枚とサムネイル・`manifest.json` | プリセットの一覧が空になる |
| `licenses/` | 168KB | AGPL 全文・第三者表記・書体14種の OFL | ［このアプリについて］のリンクが 404 |
| `fonts/` | 8KB | 源暎こぶり明朝のライセンス全文 | 同上 |

> **書体の実体は `assets/` に入っている**(ファイル名にハッシュが付く)。
> `fonts/` はライセンス文だけなので、名前から量を推し量らないこと。

### 文字コード

`licenses/` と `fonts/` のライセンス文は **UTF-8** です。Xserver の
`AddDefaultCharset` が UTF-8 以外だと、著作権者名(「おたもん」など)が化けます。
化けたら `.htaccess` に次を足す:

```apache
AddDefaultCharset UTF-8
```

**OFL は「利用者から見える形で」ライセンスを示すことを求めている**(FAQ 2.4)ので、
読めない状態は表示していないのと同じです。

## 3. 動作確認

- `https://www.hittyaka-maker.com/bookstudio/` にアクセス(www なしの URL からも、ここへ転送されることを確かめる)
- サンプル原稿で試す → プレビュー表示 → EPUB ダウンロードまで一通り確認
- PDF 出力は Chrome/Edge で「PDFに保存」できることを確認
- **「06 表紙」→［プリセット］で45枚のサムネイルが出るか**(出なければ `covers/` の上げ忘れ)
- **［このアプリについて］→「同梱している書体とライブラリの一覧」が開いて、日本語が化けていないか**

## 更新のとき

**上げ直すのは3ファイルだけです。** `npm run build` し直しても、

- `index.html`
- `assets/index-〈ハッシュ〉.js`
- `assets/index-〈ハッシュ〉.css`

の3つしか変わりません。**書体の 3,086 ファイルはファイル名が動かない**ので、
そのまま置いておけます(Vite は中身からハッシュを作るため、node_modules 由来の
書体は中身が変わらない限り同じ名前になる。実測: 再ビルドで名前が変わったのは
js と css の2つだけ)。

古いハッシュのファイルは残しておいて構いません(誰も参照しなくなるだけ)。
気になったら、`index.html` が指していないものを消してください。

## 注意

- 利用者の原稿データはサーバーに送信されません(すべてブラウザ内で処理)。アクセスログ以外に個人情報は発生しません
- **AGPL 第13条**により、Web で提供するならソースの入手先を画面から示す必要があります。
  ［このアプリについて］に置いてありますが、**リポジトリが public になっていないとリンクを出しても入手できず、義務を果たしたことになりません**。
  公開の順番は「リポジトリを public にする → サイトへ上げる」
