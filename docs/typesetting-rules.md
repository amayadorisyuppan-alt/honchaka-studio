# ひっちゃか本づくりスタジオ 本文組版デザインルール v0.2(2026-07-19)

目的: 原稿を流し込むだけで「本らしい」紙面・EPUB になるための既定値と禁止事項を定める。
新アプリ(日本版 Kindle Create)の組版エンジンの仕様書を兼ねる。

準拠: JIS X 4051(日本語文書の組版方法)/ W3C 日本語組版処理の要件(JLReq)/ Amazon KDP 印刷仕様

---

## 0. 大原則(この5つを守るだけで「本」に見える)

1. **版面はグリッドで決める** — 本文領域は「文字サイズ×字詰」と「行送り×行数」の整数倍にぴったり一致させ、端数は余白に逃がす。半端な行・ページ下端のガタつきはここで根絶する。ただし端数は**片側に押しつけず、ノド:小口・天:地の比を保って配る**(§1.1-5)。
2. **行送りは本文サイズの 1.5〜2.0 倍** — 文芸縦書き 1.7 倍前後、実用横書き 1.8 倍前後を既定とする。
3. **1行の長さに上限** — 縦書き 38〜42 字、横書き 35〜40 字。超える判型では段組みにするか余白を増やす。
4. **段落は全角1字下げ・段落間ベタ(空きなし)** — Web 風の「空行区切り・字下げなし」は本文に持ち込まない(実用書テーマのみ切替可)。
5. **書体は2つまで** — 本文=明朝1書体、見出し=ゴシック1書体。階層はサイズと太さで作り、書体数を増やさない。

---

## 1. 版面設計(紙)

### 1.1 自動計算ロジック(アプリの中核仕様)

1. 判型・組み方向を選ぶ
2. テーマ既定の本文サイズ・行送り倍率を取る
3. 余白の下限(天・地・小口・ノド=KDP規定)を確保する
4. 残り領域に収まる**最大の整数**字詰・行数を算出する
5. 版面を引いた端数を**ノド:小口 = 1.4:1、天:地 = 1:1.25** の比で配分して版面を確定する(下限は必ず満たす)

> 前版の「デザイン崩れ」の主因はこのグリッド整合の欠如。字詰・行数をユーザーに直接入力させず、判型+文字サイズ+余白から**必ず整数で導出**する。

> **端数を小口・地だけに吸収させてはいけない**(2026-08-10 修正)。字詰の上限(§0-3)に当たる判型では
> 余りが大きく、小口がノドの2倍近くまで膨らむ。実際に KDP へ入稿した B5 横組みで
> **ノド 17.0mm / 小口 30.9mm** を実測した(1:1.8)。くるみ製本は綴じ側が湾曲するため、
> 綴じ側こそ広くないと厚い本で読めなくなる。比の 1.4 は出版済みペーパーバックの実測値
> (ノド:小口 ≒ 1.41)に合わせている。

### 1.2 KDP 制約(下限値)と、出し先ごとの決まり

**ノドの下限と塗り足しは出し先で決まる**(2026-10-01)。KDP の本は下の KDP の決まりで固定。
出し先が「その他の印刷所」の本は、利用者が入れた数字(`PrintRules`。models/project.ts)で決まる。
入っていない本(古い保存の印刷所の本)は、いままでどおり KDP の決まりで組む(黙ってノドと用紙が変わらないように)。

| 項目 | KDP | その他の印刷所(`printRules`) |
|---|---|---|
| 塗り足し | 天・地・小口に 3.2mm、ノド側なし | 幅 `bleedMm`(既定 3mm)。ノドにも付けるか `bleedGutter`(既定は付ける=四辺) |
| ノドの下限 | 下の表(総ページ数で5段) | `gutterMinMm`(既定 15mm)。`thickPages` をこえたら `thickGutterMm`(既定 200ページ超で 20mm。決まりが無ければ両方 null) |
| 表紙の塗り足し | 四辺 3.2mm | 本文と同じ幅(四辺) |

- `thickGutterMm` は読むとき `gutterMinMm` 以上に切り上げる(`printRulesOf`)。ページ数で下限が**下がる**と、
  推定ページ数の書き戻しが「201ページ→10mm→199ページ→15mm→201ページ…」と振動するため。
- 横組みは、どちらの出し先も下限に**行末の句読点のぶら下がり1字ぶん**を足して組む(`gutterNeedMm`)。
- 範囲: 塗り足し 0〜10mm・ノドの下限 0〜50mm・ページ数 1〜2000(`PRINT_RULE_LIMITS`。欄・読み込み・`printRulesOf` が同じ範囲を見る)。

KDP の表:

| 総ページ数 | ノド余白(下限) |
|---|---|
| 24〜150 | 9.6mm |
| 151〜300 | 12.7mm |
| 301〜500 | 15.9mm |
| 501〜700 | 19.1mm |
| 701〜828 | 22.3mm |

- 天・地・小口: 塗り足しなし 6.4mm 以上/塗り足しあり 9.6mm 以上(あくまで下限。実際は下表の目安値を使う)
- 塗り足し ON 時(KDP): 仕上がり寸法に対し幅 +3.2mm(小口側)、高さ +6.4mm(天地各 3.2mm)。ノド側には足さない
- 印刷所の本は 幅 +(小口 + ノド)、高さ +(天 + 地)。四辺 3mm なら仕上がり +6mm × +6mm(文庫 111×154mm)。
  **足し算にはかっこを付ける**(`trim.h + (top + bottom)`)。順に足すと判型 12 個中 8 個で末尾の桁が変わり、KDP の組版が1字変わる

**アプリは常に塗り足しありで書き出す**(2026-08-11 決定。塗り足しの幅は 0 にもできるが、既定は付ける)。
全面画像を出すには塗り足しが必須で、用紙を後から広げると版面をやり直すことになるため、
最初から塗り足し込みの寸法で組む。

| 判型 | 仕上がり | 入稿する用紙 | 全面画像@300dpi |
|---|---|---|---|
| 文庫(A6) | 105×148 | 108.2×154.4 | 1278×1824 |
| 新書 | 103×182 | 106.2×188.4 | 1254×2225 |
| B6 | 128×182 | 131.2×188.4 | 1550×2225 |
| 四六判 | 127×188 | 130.2×194.4 | 1538×2296 |
| A5 | 148×210 | 151.2×216.4 | 1786×2556 |
| B5 | 182×257 | 185.2×263.4 | 2187×3111 |
| A4 | 210×297 | 213.2×303.4 | 2518×3583 |

余白は「用紙の端から測って」天・地・小口に +3.2mm、ノドは据え置き(KDP)。
印刷所の本はノドにも塗り足しを足す(`gutterM = ノド + ノド側の塗り足し`)。**版面の幅は `用紙の幅 − gutterM − foreM`**
(= 仕上がり幅 − ノド − 小口)で、ノド側の塗り足しを引かないと版面がそのぶん広がる。
こうすると仕上がりから見た版面の位置が塗り足しなしのときと一致する
(2026-10-01 実測: 塗り足しだけを変えた本は、KDP の本と全文字の位置の差が 0.05mm 以内。scripts/check-bleed.py。Chrome が用紙を px に丸めるぶん)。
背景・全面画像・大扉は用紙全面の中央に置くので、**KDP は紙の中央が仕上がり中央から 1.6mm ずれる**
(KDP の断裁誤差(±3.2mm)より小さいので許容している)。**四辺に付けた印刷所の本は、ずれない。**
ノド側に付けない印刷所の本は KDP と同じく塗り足しの半分(幅 3mm なら 1.5mm)ずれる。
**大扉の左右の余白**は、印刷所の決まりが入っている本だけ `max(小口側, ノド側)` の左右対称にする(css.ts の `titleM`)。
小口側のままだと、横組みで書名が長いとき 1 ページ目(右ページ)の字がノドの下限を割る(2026-10-01 実測: 文庫・横組み・下限 15mm・書名 38 字で 13.5mm)。
KDP と決まりの無い本は、いままでどおり小口側の式のまま(組版HTMLは変えない)。scripts/check-bleed.py の 4b が測る。

KDP の `@page` の中のコメント(「用紙 = 仕上がり + 塗り足し(小口 +3.2mm / 天地 各 +3.2mm)」)も出力に入るので、
KDP の本ではその一字も変えない(印刷所の本は4辺の数字を言う)。

CSS の `bleed` プロパティは Vivliostyle では効かない(`@page :recto/:verso` に書いても無視され、
「ノド側だけ足さない」非対称も作れない)ので、`@page { size: … }` を広げて余白を足す方式で作っている。

### 1.2b 中綴じ(2026-10-03。`settings.binding`)

ZINE・薄い本は、紙を重ねて真ん中をホチキスで留める**中綴じ**が多い。出し先が中綴じの決まりを持つとき(その他の印刷所など。
`PrintTargetProfile.saddle`)だけ、［本のかたちを決める］に［綴じ方］が出る。**KDP には中綴じが無い**ので欄を出さず、
中綴じを選んだ本を KDP に切り替えても選びは消さない(`bindingOf` が無線として組む。画面と入稿前チェックで「無線綴じで組んでいます」と言う)。
項目の無い古い保存は無線(組版は1字も変わらない。layout-matrix の 252 行の指紋が前後で同じ)。

| 項目 | 中綴じ | 無線綴じ(塗り足し四辺 3mm の印刷所) |
|---|---|---|
| 塗り足し | **無線と同じ四辺 3mm**(`bleedOf` は触らない。2026-10-03 監査: 入稿ガイドは「四辺に 3mm」がふつうで、ノド側なしが正しいと分かったときだけ分岐を足す) | 同じ |
| ノドの下限 | **10mm**(片側。`SaddleSpec.gutterMinMm`。ページ数で増えない) | 15mm(200ページ超は 20mm) |
| 余りの配り | ノド:小口 = **1:1**(根元まで開くので、くるみ製本の 1.4 ではない。字詰め・行数は変わらない) | 1.4:1 |
| 総ページ数 | **4 の倍数**(上限 48。いちばん薄い本文用紙で 60) | — |
| 綴じる辺 | 判型の高さが 150mm 以上が目安(文庫 148mm は「印刷所に相談」と知らせる。止めない) | — |
| 背幅 | 0(背なし) | 印刷所の数字 / 紙の厚み × ページ数 |
| 表紙の既定 | **別表紙**(表4＋表1 を直結した1枚。横幅 = 塗り足し + 判型の幅 × 2 + 塗り足し。A5 なら 302×216mm の仕上がり 296×210) | 表4＋背＋表1 |

- **ノドの下限の分岐は `printRulesOf` より先に置く**(`gutterFloorMm`)。決まりが固定の会社は無線のノド 15mm が返ることがあり、後に置くとそちらが勝つ。
  `printRulesResult` の「ノドは 15mm 以上…変えられません」も、中綴じは「10mm 以上」と言う。
- **白いページ(`typeset/saddle.ts` の `saddlePad`)**: 本文 n0 ページ(白も表紙も含まない)に対し、足す枚数は `pad = (4 − n0 mod 4) mod 4`。
  **奥付の手前**に `<div class="plate blank" data-pad>` で入れる(奥付が最後の本文ページになる。奥付の無い本は本文の最後)。
  自分で置いた挿絵・白ページは「奥付の前」に入っているので、そのぶん自動の白は減る。`data-plate` は付けない(差し込みページ一覧に出さない)。
- **収束(App.tsx の `saddlePadCount`)**: 白の枚数は組み上がったページ数から決まる画面の状態(保存しない)。組んだ HTML の
  `<meta name="studio-pad" content="白 表紙">` を読んで n0 = 総数 − 白 − 表紙 を戻し、`pad` が違えば直して組み直す。n0 は白に依らない
  (白は本文のあと)ので、書き戻しは1回で収まり、**1回の編集で組み直しは多くて2回**(本文の1回と白の1回。`scripts/check-saddle.py` の B が測る)。
  ノドの下限の書き戻し(`estimatedPages`)と**同じ effect の中で、順番を決めて**走らせる(中綴じのノドは一定値なので、2つが同時には動かない)。
  4 の倍数にそろう前は、書き出しの主ボタンを押せなくする(`printBlockedReason` に `blockReason` で渡す)。
- **共紙**(表紙も本文と同じ紙): 表1・表2(白)を本文の**先頭**、表3(白)・表4 を**末尾**(奥付のあと)に入れる(計4ページ。4 の倍数なので pad の式は変わらない)。
  表1・表4 は `div.plate.full` の絵(300〜350ppi の PNG)。**書き出しのときに表紙エディタから切り出す**(`CoverEditor.renderFaces`。
  本文の用紙と同じ大きさで、小口の端をそろえて切る)。下見は仮の枠(`coverFaces: 'placeholder'`)で、表紙を直すたびに本文を組み直さない。
  ページ番号は PDF のページ番号と同じ(表1 が 1)で、奇数・偶数は保たれる(大扉は 3 ページ目)。
  **白黒の本の共紙は表紙も白黒(K1色)で刷られる**・**文字も絵と同じ画像になる**ことを、画面で知らせる。［表紙］の書き出しカードは出さない。
- 未着手: 見開きにまたがる絵(D1 の S6)、その他の印刷所の中綴じの欄(ノド下限・上限ページ。いまは よくある入稿ガイドの初期値)、
  `PressJob.expectMultipleOf`(変換パイプラインでの 4 の倍数の点検。画面側の検査で当面足りる)。
- 検査: `scripts/saddle.test.ts`(純関数・保存・組版HTML)、`scripts/check-saddle.py`(PDF の実測と、アプリごとの収束)。

## 2. 文字と行

- 本文書体: 選択制(既定は 文芸テーマ=Noto Serif JP 400 / 実用テーマ=Noto Sans JP 400)。
  **見出し・柱・ノンブルはゴシック固定**で、本文を変えても連動させない(§0-5「書体は2つまで」)
  - 収録字数はどれも 17,000〜18,500 字あり、第2水準・旧字とも本文で困らない(2026-08-11 実測)
  - 太字(`<em>`)は**その書体が実際に持つウェイト**を指定する。持たない値を書くとブラウザが
    合成太字を作って字面が潰れる(源暎こぶり明朝・Klee One など)
  - **組版HTMLに `@font-face` を必ず同梱する**(typeset/fontface.ts)。
    アプリ本体のCSSは印刷経路(iframe)にも CLI にも届かず、無いと游明朝などに黙って置き換わる
- **ベタ組が原則**(letter-spacing 0)。均等割付・自動字間調整はしない
- 強調: 太字は同書体の 700。斜体は日本語では使わない(傍点で代替、Phase 2)
- 縦書き中の英数字: 1〜2桁の数字は縦中横(§5)、3桁以上は全角にして1字ずつ正立。欧単語は横倒しのまま
- 横書き中の英数字: 半角。和文と欧文の間に四分アキ

## 3. 段落

- 全段落 `text-indent: 1em`、段落間マージン 0
- 「 や ( で始まる段落(会話文)は字下げしない(決定済み。アプリでは切替可)
- 原稿中の空行 1 つ = 場面転換の 1 行アキとして保持。2 連続以上は 1 行アキに丸める
- ページ末尾・先頭の孤立行制御: orphans/widows は 1 行を許容(日本語文芸の慣行。厳密制御は行グリッドを乱すため)

## 4. 禁則・約物(JIS X 4051 準拠)

- 行頭禁則: 。、)」』】〉》…ゃゅょっー々 など(小書き仮名を含む strict)
- 行末禁則: (「『【〈《 など
- 分離禁止: 「……」「――」は 2 字 1 組で行分割しない
- ぶら下がり: 句読点のみ許可=ON(決定済み)
- 連続する約物は詰める(例: 」「 の間を半角分に)
- 「?」「!」の後、文が続く場合は全角アキ

## 5. 縦書き固有ルール

- ルビ: 親文字の 0.5 倍、モノルビ基本。青空文庫記法《》を取込時に変換
- 縦中横: 半角数字 2 桁まで自動適用(「19」「10月」など)。「!?」「!!」も 1 組で縦中横
- 3 桁以上の数字: 全角化して 1 字ずつ正立(決定済み。アプリでは横倒しも選択可)
- **縦中横の適用漏れに注意**: 「!?」「!!」も対象。取込処理で半角の連続数字・感嘆符を機械的に検出して `.tcy` を付与し、目視に頼らない

## 6. 見出しと章構成

- 見出しは**本文の行グリッドの整数行取り**にする(これがページ下端を揃える肝):
  - 章(見出し1): 改ページ起こし+**5 行取り**。ゴシック、本文の 1.6 倍
    - 章は奇数・偶数どちらのページから始まってもよい(単純改ページ)。ただし**本文の開始(第1章の1ページ目=P1)だけは奇数ページ起こし**にする(決定済み 2026-07-19)
    - 章番号(「第三章」など)と章題は**ワンセットで行を詰めて組む**: 章番号=本文サイズ・1行、直後に章題=1.6倍・1行。セットの後に**2行程度のアキ**を置いてから本文を開始する。セット+アキで計5行取り
  - 節(見出し2): **3 行取り**。ゴシック、本文の 1.2 倍。前にアキがくるよう配置
  - 小見出し(見出し3): **2 行取り**。ゴシック太字、本文と同サイズ
- 見出しの直後で改ページさせない(`break-after: avoid`)
- ページ最下部に見出しだけ残る場合は次ページへ送る
- 章の本文は見出しブロックの直後から行グリッドに乗せて開始

## 7. ノンブルと柱

- ノンブル: 地の小口寄り。本文の 0.85 倍、欧文書体の数字
- 柱: 奇数ページに章題のみ(偏柱)。地の小口寄り、ノンブルの内側
- **柱とノンブルは字の並ぶ線(ベースライン)を一本にそろえ、本文から 1.5mm 離す**(2026-10-03)。仕上がり端から字の下端まで KDP 6.4mm(会社の規定があればその値。PrintTargetProfile.safeAreaMm)を割らない。天に置いても同じ(css.ts の anchorFor・markBaseMM。scripts/check-footer.py で紙を測る)
- **扉・中扉・目次・奥付・白ページにはノンブル・柱を刷らない**(隠しノンブル)
- ページ番号は通しで数え、前付では非表示(決定済み)

## 8. 前付・後付

- 構成順: 本扉 →(献辞)→ 目次 → 本文 →(あとがき)→ 奥付
- 本扉: 書名・著者名。版元名は入れない(奥付に記載する)。**左右の余白を揃えて組む**
  (枠ものの背景画像を敷いたとき、書名が枠の中で偏らないようにするため)
  - **縦組みの本では、書名・著者名だけ横組みにできる**(`settings.titleWritingMode`。2026-10-03。省略は本文に従う=いままでどおり)。
    表紙の表1・大扉・電子書籍の扉に効く。柱・奥付は紙ではもともと横組み。**綴じの向き・表1の左右・背は `writingMode` のまま**で、書名の向きのために動かさない。
    大扉は、縦組みのページに横組みの器を置くと幅が版面幅にならず細くなる(奥付と同じ実測)ので、幅と高さを実寸で与える。
    書名は縦中横を掛けない。scripts/check-title-horizontal.py(紙)・scripts/check-title-cover.py(表紙)が測る。
    **電子書籍の扉も追従する**(2026-10-03)。扉の XHTML の `html` 要素だけ `class="tp-h"` を付けて横組みに戻し(`html.tp-h { writing-mode: horizontal-tb }`)、
    横組みの本と同じ table の中央寄せを重ねる。ほかのページと `page-progression-direction` は本文の向きのまま。
    Kindle・Apple Books・Kobo の実機での見え方は未確認(崩れる機械があれば、扉だけ本文に従う形に戻せる)。
    **下見は向きを変えても本全体を組み直さない**(src/preview/paint.ts の「向きだけ」)。大扉は独立した1ページ(`break-after: page`)で、
    ページ数もほかのページの字の位置も動かないので、下見の組版には縦のままを固定して渡し(`paintNeutral`)、
    大扉の規則(`titleHorizontalDecls`。紙の組版CSSと同じ宣言)だけを `!important` で重ねる。縦用と横用で字の並びが変わる書名
    (数字・！？の縦中横と全角化)は、下見の組版HTMLに両方を入れて(`manuscriptHtml` の `titleBothWays`)CSSで選ぶ。
    紙の書き出しは完全な設定から組むので、そのときの向きの1つだけが入る。scripts/check-title-switch.py が実際の組版器で測る
- 目次: 章題+ノンブルをリーダー(……)で接続。目次自身は載せない。あとがきがあれば載せる
- あとがき: 本文の後・奥付の前。章と同じ体裁(改ページ起こし・5行取りの見出し)
  - **短ければ奥付と同じページに載せる**(2026-08-11 決定)。奥付だけの白いページを作らない。
    組む前に行数を文字数から見積もり、2行の余裕を持って収まるときだけ同居させる。
    届かなければ従来どおり別ページ(保守的に外しても損がない側に倒す)
- 挿絵ページ: 1枚絵で1ページ。原稿には書かず、取り込んだあとにアプリで足す
  - **置けるのは章の切れ目だけ**(2026-08-16 決定)。指定は「◯章の前」で、実質は前の章の末尾。
    章はもともと改ページ起こしなので、ここに挟んでも本文の流れが動かない。
    以前は「◯ページ目に置く」で指定していたが、判型や段組みを変えるとページの見積もりが
    陳腐化して絵が別の場面に飛んだ。**指定できる場所を減らすことで、ずれる余地をなくした**
  - 大きさは 全面(塗り足し込み) / 余白すこし(仕上がりの外周4%) / 余白おおめ(同20%) / 版面いっぱい。
    **余白は本文の版面から取らない**。ノドの広い判型で挿絵まで寄って見えるのを避ける
  - **版面いっぱい(2026-09-30 追加)だけは本文と同じ余白の内側に収める**(`@page printplate`)。
    KDP は絵の中に描かれた文字も検出し、余白に出ていると刷れない(ユーザーの知見)。
    文字の入った図表のための大きさで、絵の端まで文字があっても余白に出ない
  - **見開き(2ページ)(2026-10-03 追加。章の切れ目の挿絵ページだけ。章の途中の絵には無い)**: 1枚の横長の絵を、向かい合う2ページに分けて入れる。
    - 向かい合う2ページ = **偶数ページから始まる2ページ**(縦書き・右綴じも横書き・左綴じも)。
      1ページ目の絵に `break-before: verso`、2ページ目に `break-before: recto`。奇数ページに来るときは組版エンジンが
      白いページを1枚入れる(章の起こしの `recto` と同じ仕組み)。**黙って足さない**: 入れたことは［挿絵］のその絵の行で知らせる
      (組み上がりの DOM で、手前のページが「中身が空」かを読む。`preview/VivliostylePreview.tsx` の readLayout)。
      自分で前に絵やクッションを足して偶奇を合わせれば入らない。中綴じの白いページ(奥付の手前)とは位置が別で、ぶつからない
    - 左右: 縦組み(右綴じ)は1ページ目=絵の右半分・2ページ目=左半分、横組み(左綴じ)は左半分・右半分(本を開いた見た目どおり)。
      偶数ページのノド側が折り目に向く(`pdfx.ts` の pageBoxesPt・`scripts/check-bleed.py` の `gutter_on_left` と同じ決まり)
    - 絵は「仕上がり2枚 + 小口の塗り足し2つ」×用紙の高さの四角に、全面と同じ**中央切り出し**(`object-fit: cover`)で敷く。
      各ページの用紙(塗り足し込み)で切るので、**折り目の側はノド側の塗り足しの幅だけ反対側の絵まで入る**
      (KDP はノド側 0 で重ならず、印刷所の四辺 3mm は両ページに 3mm ずつ重なる)。断裁がずれても白い筋が出ない。
      ノンブル・柱は出さない(`@page plate`)
    - 中綴じにいちばん向く(根元まで開く)。中心±5mm に顔・文字・細い線を置かない(綴じ・折り・断裁で ±1mm ずれる。背景や大きな面はまたいでよい)。
      無線綴じでも選べるが、真ん中が糊で隠れて見えにくくなる(片側 10mm ほど)と知らせる
    - 電子書籍は、端末で見開きの見せ方がばらばらなので、1ページに横長の絵をまるごと縮めて入れる
    - 絵の中の文字の検査・解像度の知らせは、用紙2枚ぶん(`spreadArtMm`)で効かせる。折り目の左右 5mm に文字があるときも知らせる
    - **文字の検査の折り目側は、いま効いている綴じ方(`bindingOf`。KDP は中綴じを選んでいても無線)で変わる**(2026-10-05。`judgeSpreadText` / `findTextOutside` の `binding`):
      - 無線綴じ: ノド側も版面で見る(真ん中は糊に食われる・KDP も余白の外の文字は止める)→ 強い知らせ(「版面の外に出ています…入稿で止められることがあります」)
      - 中綴じ: 本が根元まで平らに開くので、ノド側の版面の余白は使わない。折り目から左右 5mm にかかる文字だけ、やわらかい知らせ(`foldOnly`。「読みにくくなることがあります」。下見は赤でなく `--warn` の色)。5mm より離れていれば何も言わない
      - 天・地・小口は、どちらの綴じ方でも版面で見る(外なら強い知らせ)
    - 計算は `src/typeset/spread.ts`(純関数)。検査は `scripts/spread.test.ts`(純関数・組版HTML・文字の検査)と `scripts/check-spread.py`(紙で測る)
  - **章の途中に絵を入れたいときは、本文の画像ブロックとして入れる**(2026-09-23 決定)。
    ［挿絵］で段落を選ぶと、その段落のあとに入る。位置は「どの段落のあとか」だけなので
    判型を変えてもずれない。以前は Word に書き出して貼り、取り込み直す往復だったが撤去した
  - 章の途中でも大きさは挿絵ページと同じ4つ(全面/余白すこし/余白おおめ/版面いっぱい)を選べ、
    **同じ箱(`div.plate` / `div.fullbleed`)で組む**。その段落のところで改ページするので、
    前のページの下が空くことがある。これは避けられない(置く段落を選び直してもらう)
- 奥付: 最終ページに配置。書名/著者/発行日/発行者・発行所/©表記/(あれば)ISBN。KDP ペーパーバックは印刷所表記不要
  - **版面の地に寄せ、上に細い罫を引く**(2026-08-11 決定)。天ぞろえだと奥付に見えない
  - **縦組みの本でも奥付だけは横組み**にする(現代の和書で最も一般的な体裁)。**紙の本の話。**
    EPUB では奥付・著者紹介も本文と同じ向きで流す(2026-09-24 ユーザー判断。縦組みのページの中に
    横組みの箱を入れる「組み方向の入れ子」は電書連ガイドが勧めず、Apple Books は組み方向を html/body にしか認めない)
- 本文中の画像: 版面(段組みなら1段ぶん)に収まるまで縮める
  - **縦組みは段の天に寄せ、本文を回り込ませる**(2026-08-16 決定)。縦組みでは画像の「幅」が
    行の並ぶ方向なので、帯として置くと高さが余っていてもその幅ぶんの行が丸ごと消える
    (実測: 横長の絵1枚でページの本文が 0行になった)。回り込ませれば絵を縮めずに行が戻る
  - **1段の縦組みは、置いた段落のあるページの天・行頭の角に寄せる**(ページフロート。2026-09-29 決定)。
    置いた段落の位置で組むと、版面いっぱいの絵はページの途中でまず入りきらず、後ろの本文ごと
    次のページへ送られて送り元に空きが残る。送られた先でも絵の前のアキ(1行)が消えず、
    絵が版面の端から1行ずれていた(ユーザー報告「最初の行から画像がきれいに入らない」)。
    角に寄せれば前後の本文が絵の下へ回り込んでページを埋める。そのページに入らない絵は
    次のページの頭に置き、本文は先に流す。**段組みではやらない**(下の段に置いた絵が上の段へ飛ぶ)
  - **章だけ段数・文字サイズ・行送りを変えた章は、その章の1段で大きさと置き方を決め直す**
    (2026-09-29 決定)。版面の四角は本全体で1つなので、章はその四角を自分の段数で割る。
    本全体の値のままにすると、1段の本の中の2段の章で、下の段に置いた絵が版面の地を越えて
    ノンブルに重なった(B6 で実測: 約20mm)。回り込ませるか・ページの天に寄せるかも章の段数で決める。
    **段組みの本の中の1段の章は、1段の本と同じくページの天に寄せる**
  - **横組みは版面の左右中央**。横組みでは画像は天地方向を使うだけで行は減らないので、
    回り込ませる必要がない
  - **余白は論理方向(`margin-block`/`margin-inline`)で取る**。縦組みで物理 margin-top/bottom を
    使うと段の天地を食い、画像が段からはみ出して柱・ノンブルに重なる
  - 入る場所は「どの段落のあとに置いたか」だけ。Word 上でドラッグしたページ内の座標は、
    判型や段組みを変えれば組み直すので引き継がない
  - **原稿を取り込み直しても、スタジオで置いた絵は残す**。前にあった段落の字で同じ場所を探して
    付け直し(書き出しか終わりが同じなら直した段落も拾う)、見つからなければその章の最後へ
    絵のまま移す。Word に貼ってあった絵は原稿の側から戻るので付け直さない
- 章の始まりは必ず新しいページ(§6)

## 9. リフロー EPUB への適用

| | 紙とルール共有 | 読者環境に委ねる(指定しない) |
|---|---|---|
| 対象 | 書体系統(明朝/ゴシック)、行送り倍率(相対値)、字下げ、禁則、ルビ、縦中横、見出し階層と改ページ、扉・目次・奥付 | 文字サイズの絶対値、版面・余白、字詰・行数、ノンブル、柱 |

- 文字サイズは指定せず基準 1em。見出しは em 倍率、余白はすべて em 単位
- 縦書き: spine に `page-progression-direction="rtl"`、`primary-writing-mode: vertical-rl`
- 画像は `max-width: 100%`(縦書きでは `max-height: 100%` も)

## 10. CSS 実装対応表(Vivliostyle)

| ルール | CSS |
|---|---|
| 判型 | `@page { size: 105mm 148mm; }` |
| 塗り足し | `@page { size: 用紙幅 用紙高; margin: 天+塗り足し ノド+塗り足し 地+塗り足し 小口+塗り足し; }`(CSS の `bleed` は Vivliostyle で効かないので、size を広げて余白を足す。トンボは付けない) |
| 縦書き | `html { writing-mode: vertical-rl; }` |
| 行グリッド | 本文 `line-height` を pt 固定値で指定。見出しの高さ=行送り×n 行(行取り) |
| 禁則 | `p { line-break: strict; word-break: normal; overflow-wrap: break-word; }` |
| ぶら下がり | `hanging-punctuation: allow-end;` |
| 約物詰め・和欧アキ | `text-spacing`(Vivliostyle の対応状況を実装時に確認) |
| ルビ | `rt { font-size: 0.5em; }` |
| 縦中横 | `.tcy { text-combine-upright: all; }`(取込時に 2 桁数字へ自動付与) |
| 段落 | `p { margin: 0; text-indent: 1em; }` 会話文は `.no-indent` |
| 章改ページ | `.chapter { break-before: page; }`。本文先頭(P1)のみ `break-before: recto;` |
| 見出し孤立防止 | `h2, h3 { break-after: avoid; }` |
| ノンブル | `@page :left { @bottom-left { content: counter(page); } }` ほか |
| 柱 | `h1 { string-set: chapter content(); }` + `@page` マージンボックスで `string(chapter)` |
| フォント | `@font-face` でサブセット化した Noto を同梱。EPUB は埋め込み+読者設定を尊重 |

## 11. アンチパターン(「本に見えない」原因チェックリスト)

1. 余白が狭く紙面いっぱいに文字が詰まっている
2. 行間が詰まりすぎ(1.5 倍未満)またはスカスカ(2 倍超)
3. 段落間に空行があり字下げがない(Web の体裁)
4. 見出しが中央揃え・装飾過多・書体バラバラ
5. 見出しが行グリッドに乗らず、ページ下端が頁ごとにガタつく
6. 行頭に句読点が来ている(禁則未処理)
7. 縦書きで半角数字が横倒しのまま(「19」が寝ている)
8. 章がページの途中から始まる
9. 扉や奥付にまでノンブルが刷られている
10. 柱がない・全ページ同じで現在位置が分からない
