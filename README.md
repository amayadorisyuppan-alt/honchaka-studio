# ひっちゃか本づくりスタジオ

Word やテキストの原稿を渡すだけで、**縦書きでも横書きでも、電子書籍(EPUB3)と KDP 入稿用の紙書籍 PDF** をブラウザだけで作れる Web アプリ。米国版 Kindle Create が日本語非対応である空白を埋めるもので、あまやどり出版の公式サイトで無料公開する想定。

- 完全クライアントサイド処理:原稿・画像・個人情報は一切サーバーに送信されない
- 組版エンジン: [Vivliostyle](https://vivliostyle.org/)(CSS組版・AGPL)をブラウザ内で実行
- 自動保存: ブラウザの IndexedDB(操作の 0.8 秒後に保存)。本文の設定・原稿・表紙のデザインまで丸ごと復元する
- クレジットとライセンスは画面右上の［このアプリについて］に。ソースの入手先もここ(AGPL 第13条)
- 自動バックアップ: 選んだローカルフォルダへ、画像込みの完全な控えを世代つきで書く(Chrome / Edge)
- 画面は**作業の順番**に並ぶ。`本文に画像を入れる → 奥付と著者紹介を入れる → 表紙をつくる → AI に手直ししてもらう → 完成データを書き出す`（番号は振らない。ラベル自体がやることなので意味を持たない）
- 原稿の出し入れ(取り込む / 続きを開く / サンプルを見る)は工程ではなく**入口画面**。アプリ名の横の［最初の画面に戻る］でいつでも開く
- 入口のサンプル本は、下のボタンのほか**本の左右の矢印と ← → キー**でもめくれる(右綴じなので ← が次)
- 判型・組み方向・段組み・目次・刷り色・書体・文字と行は工程ではなく**画面下の帯**。
  一度決めて次へ進むものではなく、絵を入れながら・表紙を作りながら変えたくなるので、どの画面でも手元にある

> **開発中**。作り直しの経緯・実装上の地雷・引き継ぎの文書は、公開しない資料としてリポジトリの外で管理している。
> このリポジトリの `docs/` には、組版ルール(`typesetting-rules.md`)・公開手順(`xserver-upload.md`)・組見本を置く。

## 対応環境

無料・無保証(AGPL)。そのかわり、**「対応」の範囲で起きた不具合は直す。範囲の外は、開けることがあっても直せない。**

**対応**(不具合は直す)

- パソコン: **Windows 10・11、Mac(macOS 13 Ventura 以降)**
- ブラウザ: **Google Chrome か Microsoft Edge の新しい版**(版の先頭が 128 以上)。作るときの確かめはこの2つで行っている。自動バックアップ(フォルダへの書き込み)と画像のフォルダ(フォルダを選ぶ)は、この2つだけで使える
- 原稿: Word(.docx)・テキスト(.txt)・Markdown(.md)。**見出しとルビの読み取りは Word だけの特別対応**(テキストと Markdown は記号で書く)

**対象外**(直せない)

- スマホ・タブレット(画面が狭く、仕上がりの確認や操作ができない)
- Windows 7・8・8.1・Vista・XP(新しい Chrome・Edge が入らない) / macOS 12 Monterey 以前(最新の Chrome・Edge が入らず、更新も止まる)
- Mac の Safari(Safari と同じ仕組み(WebKit)で試したところ、**同じ本でもページ数が Chrome と変わった**(40 と 42)。今は対象外。落ち着いてから見直す)
- Firefox、古い版の Chrome・Edge(128 より前)
- Pages・Google ドキュメント・一太郎などの書類そのまま。**Markdown かテキストにすれば使える**(テキストは「第一章」などの行で章に分かれる。AI に頼めば Markdown に書き換えてくれる。Google ドキュメントは［ファイル］→［ダウンロード］→［Markdown(.md)］で直接書き出せる)

入口では、対応環境の外の人にだけ一言知らせる(止めはしない)。

**そのほか**

- パソコンの性能: メモリ 8GB 以上(写真の多い本は 16GB)。約300ページの本で、組み上がりに 30 秒〜数分(パソコンの速さによる)
- 画面の横幅: 1280 ピクセル以上がおすすめ(1024 でも使える)
- インターネット: 開くとき・書体を初めて使うとき・入稿用の変換のときに使う。**原稿と画像はどこにも送らない**(このパソコンのブラウザの中だけで作る)

## 実装済みの機能

| 機能 | 内容 |
|---|---|
| 原稿取込 | Word(.docx: 見出し1で章分割・見出し2/3は小見出し・**画像も貼った位置のまま取り込む**) / テキスト(.txt: 章の自動検出) / Markdown(.md) |
| ルビ | 青空文庫記法(`漢字《かんじ》`・`｜親文字《るび》`)を `<ruby>` に変換 |
| Markdown 記法 | `**強調**` は太字で組む。リンク・コード・箇条書き・引用・脚注はマーカーを落として本文にする。表はセルを全角空きでつなぐ。`---` `***` は1行アキ。先頭の YAML front matter は捨てる |
| 縦中横 | 半角数字1〜2桁と `!?` `!!` `??` を自動で縦中横に。3桁以上は全角化して正立 |
| ダッシュ | 半角ハイフンの連続(`--`)を和文の2倍ダッシュ「――」に正規化(縦組みで横倒しになるため) |
| 組み方向 | 縦書き(右綴じ) / 横書き(左綴じ) |
| 判型プリセット | 文庫(A6)・新書・B6・四六判・A5・B5・A4 |
| 版面の自動計算 | 字詰・行数は判型+文字サイズ+余白から**整数で導出**し、端数は小口・地に吸収 |
| ノド余白 | KDP 規定(総ページ数連動)と指定値を比較して大きい方を自動採用。横組みは行末の句読点が1字ぶんノドへぶら下がるので、その1字を規定に足して比べる |
| ノンブル・柱 | 地・小口寄りにノンブル、奇数ページに柱(章題)。扉・目次・奥付・白ページには刷らない |
| 大扉 | 書名を版面の左右中央、著者名をその左下に配置。版元名は入れない(奥付に記載するため) |
| 奥付 | 書名・著者名・発行者・発行日(当日)・©表記を自動生成 |
| 目次 ★紙 | 扉の次に自動生成(ON/OFF可)。章題とノンブルをリーダーで接続し、ページ番号は縦書きでも正立させる |
| 画像 | Word に貼った画像を貼った位置のまま取り込み、**必ず版面内に収める**。代替テキストがキャプションになる(Word が自動で入れる説明文は捨てる)。推奨ピクセルはアプリが表示する。取り込んだ絵も［挿絵］の一覧に出て、場所・大きさ・キャプションを直せる |
| 段組み ★紙 | 縦組みのみ。B5・A4 は最大4段、それ以外の判型は最大3段。段間は行数で調整でき(既定1行)、章見出しは段抜き |
| 本文の刷り色 | **白黒（小説・読み物）/ カラー（ZINE・作品集）**。白黒を選ぶと、背景も挿絵も図版も**プレビューとPDFがグレーで出る**ので、刷り上がりを入稿前に確かめられる。「06 表紙」の本文用紙も刷り色に合わせて絞り込まれる |
| 入稿用のデータ ★紙 | **出し先が「その他の印刷所」のとき、［完成データを書き出す］の［紙の本文］で、保存した本文 PDF を入稿用に変えられる**(KDP は RGB の PDF をそのまま受け付けるので出さない。印刷所によっては RGB を受け付けないため)。白黒の本は **K1色**、カラーの本は **CMYK**(色の基準は Japan Color 2011 Coated。ICC を同梱)。どちらも **PDF/X-4** で、カラーは黒い字とグレーを K だけにし(文字だけのページが「カラー」と数えられない)、**インクの総量を 300% 以下**に抑え(`PRINT_TARGETS[出し先].inkLimitPct`)、できあがりに**カラーのページの一覧**を出す。**［紙の表紙］は、印刷所なら［書き出す］を1回押すだけで CMYK・PDF/X-4 まで作る**(変換に失敗したら、理由を言って RGB のまま保存できる)。Ghostscript の WebAssembly 版(AGPL)を Worker で動かし、押したときにだけ読み込む。画像は劣化させず(Flate)、変換のあとに RGB の残り・インクの量・PDF/X の形を点検して、問題があれば報告に出す。**紙の大きさがいまの本の用紙と違う本文 PDF は、保存させず、書き出し直しを案内する** |
| 電子書籍の色 | **カラー / 白黒を、紙の刷り色とは別に［本のかたちを決める］で選ぶ**(既定はカラー。`settings.ebookMono`。古い保存の `epubMono` は前に効いていた値で移す)。白黒は本文の画像(挿絵・文中の絵)にだけ `filter: grayscale(1)` を掛け、表紙はカラーのまま。電子の下見にもそのまま出る。電子書籍だけの本でも選べる |
| 本文の書体 | **15書体から選べる**(明朝7 / ゴシック4 / 装飾4)。すべて SIL OFL 1.1 で **PDF に埋め込んで出版できる**。縦組み小説向けの **源暎こぶり明朝** を同梱。見出し・柱・ノンブルはゴシック固定(ルール §0-5)。**電子書籍(EPUB)は書体を選べない: 本文は明朝、見出しと太字はゴシックで固定**(書体ファイルを入れないので、選んだ書体名はどのストアでも届かない。電子書籍だけの本と、両方の本で電子の下見を見ているときは、帯の書体の欄を固定の表示に替え、押すと大きな字の断りを出す。サイズ・行送りも同じく「読む人が端末で決めます」の表示に替え、紙だけの飾り・段組み・「◯章だけ」・［すべてリセット］は出さない — 電子を見ているあいだの帯は電子書籍だけの本と同じ)。組版HTMLに `@font-face` ごと持たせるので、印刷経路でも書体が置き換わらない |
| 余白の配分 ★紙 | 版面を引いた端数は**ノド:小口=1.4:1(中綴じは根元まで開くので 1:1)、天:地=1:1.25** で配る。端数を小口・地だけに足すと、字数の上限に当たる判型で小口がノドの2倍近くまで膨らみ、綴じ側が読めなくなる |
| 裁ち落とし ★紙 | **常に塗り足し込みの用紙**で書き出す。KDP は 小口 +3.2mm / 天地 各 +3.2mm(ノド側は足さない)で、入稿画面では「裁ち落としあり」を選ぶ。**出し先が「その他の印刷所」なら、塗り足しの幅(既定 3mm)とノド側にも付けるか(既定は付ける)・ノドの下限(既定 15mm、200ページ超は 20mm)を利用者が決める**(表紙の塗り足しも同じ幅)。余白の表示は仕上がり(断裁後)基準のまま |
| 綴じ方(中綴じ) ★紙 | **出し先が「その他の印刷所」のとき、［本のかたちを決める］の［綴じ方］で中綴じを選べる**(KDP には中綴じが無いので欄を出さない。中綴じを選んだ本を KDP に切り替えても選びは消さず、無線綴じで組んで知らせる)。中綴じは**背がなく、ページ数が 4 の倍数**: 組み上がったページ数から、**奥付の手前に白いページを足して**そろえる(「いま本文は 37 ページ。…白いページを 3 枚入れて 40 ページにします（上限 48）」と読み上げる)。ノドの下限は 10mm(無線の 15mm ではない)、塗り足しは無線と同じ四辺 3mm。**表紙は別表紙(既定。表4＋表1 を背なしでつないだ1枚)か共紙**(表紙も本文と同じ紙。表1・表4 を本文 PDF の先頭と末尾のページに入れる。［表紙］の書き出しは出さない)。文庫など綴じる辺が 150mm 未満の判型は「印刷所に相談」と知らせる。ページ数の上限(48・薄い用紙で 60)は入稿前チェックで知らせる(止めない) |
| 本文中の画像 ★紙 | 章の途中に置いた絵(［挿絵］で段落を選んで入れたもの・Word 原稿に貼ってあったもの)が、版面（段組みなら1段ぶん）に収まる大きさで入る。**縦組みでは段の天に寄せ、本文が下に回り込む**(1段の本と1段の章では、置いた段落のあるページの上に寄せるので、前のページに空きが残らない)。章だけ段の数を変えた章は、その章の1段に収まる大きさにする。縦組みは画像の「幅」が行の並ぶ方向なので、帯として置くと横長の絵1枚でそのページの本文が消えてしまう。横組みは左右中央に置く |
| 見開きの絵 ★紙 | **［挿絵］の「章の切れ目の絵ページ」の大きさに「見開き（2ページ）」**（章の途中の絵にはない）。**1枚の横長の絵を、向かい合う2ページに分けて入れる**。必ず**偶数ページから始まる**(`break-before: verso`。奇数ページに来るときは組版が白いページを1枚入れ、［挿絵］のその絵の行で知らせる。自分で前に絵やクッションを足して偶奇を合わせれば入らない)。縦組み(右綴じ)は1ページ目=絵の右半分・2ページ目=左半分、横組み(左綴じ)は左半分・右半分(本を開いた見た目どおり。左右の決まりは `pdfx.ts` の pageBoxesPt・`check-bleed.py` の gutter_on_left と同じ)。絵は「仕上がり2枚 + 小口の塗り足し2つ」×用紙の高さに中央を切り出して敷き(`object-fit: cover`)、**折り目の両ページの塗り足しにも伸ばす**(各ページ = その半分 + ノド側の塗り足しの幅だけ反対側の絵。KDP はノド側なしなので重ならず、印刷所の四辺は 3mm ずつ重なる)。ノンブル・柱は出さない。**中綴じにいちばん向く**(中心±5mm に顔・文字・細い線を置かない)。**無線でも選べる**が「真ん中が糊で隠れる(片側 10mm ほど)」と知らせる。電子書籍は1ページに縮めて入れる(`PLATE_INSET.spread` = 0)。絵の中の文字の検査・解像度の知らせも用紙2枚ぶんで効く(折り目の左右 5mm に文字があるときも知らせる。**折り目の側は綴じ方で見方が変わる**: 無線綴じはノド側も版面で見て強く言い、中綴じは版面のノド余白を使わず折り目から 5mm だけをやわらかく言う。天・地・小口はどちらも版面)。計算は `src/typeset/spread.ts`(純関数)、紙で測る検査は `scripts/check-spread.py`。**サンプルの本にも入っている**: 第二章の前に、商店街の通りの見開きの絵(4200×3000)と、文字入りの地図(版面いっぱい。3000×4200)。どちらも Pillow で描いた絵(`scripts/build-sample-art.py` → `public/sample/`。同梱プリセットの一覧には入れない)で、生成AIではないので `fromPreset` を付けず AI 申告は立たない。看板の文字は、判型7 × 縦横 × 出し先 × 無線/中綴じのどれでも「絵の中の文字」の知らせが出ない所にだけ置いてある(見開きは左右の版面の内側・折り目から 20mm 以上) |
| 全面画像 ★紙 | 章の途中の絵は大きさを「全面」「余白すこし」「余白おおめ」「版面いっぱい」にすると、そのページを1枚で占める(挿絵ページと同じ見た目)。全面は用紙いっぱい(塗り足し込み)に敷き、ノンブル・柱も出さない。Word の代替テキストの**先頭に「全面」**と書いた画像も全面になる |
| 背景画像 ★紙 | 本文と大扉に別々の背景を敷ける。**表紙用の画像パックをそのまま使える**(「04 絵」から直接選べる)。濃さのスライダーで白をかぶせて薄くする |
| 背景の上で本文を読ませる | 濃さ（絵を薄める）／文字のフチ（字を縁取る）／**本文の下に帯**の3通り。帯は**版面ぶんだけに敷かれ、余白には絵がそのまま出る**ので、絵を一切薄めずに派手な背景を使える(表紙のあらすじ帯と同じ考え方) |
| 大扉 | 左右の余白を揃えて組むので、枠ものの背景を敷いても書名が枠の中で偏らない |
| 挿絵 | 絵の入れ方は2通り。**章の切れ目に1枚絵のページを差し込む**か、**章の途中(選んだ段落のあと)に入れる**。章の途中は段落を冒頭の字で並べて選び、本文の字で本全体から探せる。位置は「どの段落のあとか」で持つので、**判型や段組みを変えても同じ場面について回る**。大きさは 本文の中 / 全面 / 余白すこし / 余白おおめ（本文の余白とは無関係）。章の切れ目の絵ページには **見開き（2ページ）** もある（上の「見開きの絵」）。表紙用の画像パックからそのまま選べる。一覧はページ順で、Word 原稿に貼ってあった絵もここで動かせる。**場所・大きさ・絵を変えると、一覧はその行へ寄り、プレビューは組み上がりを待ってそのページへ飛ぶ**(並べ直しで行を見失わないため。コラムページの場所も同じ) |
| あとがき | **本文の章として書く**。「あとがき」「おわりに」「エピローグ」などの見出しを立てれば、最後の章として組まれ、目次にも載る（専用の欄は持たない。章に番号を振らない書き方も多く、欄を1つ置いても取りこぼすため） |
| 著者紹介 | 奥付と同じページの天から、**奥付と同じ横書き・同じ文字サイズ**で入る。経歴や既刊を書く欄。**奥付と合わせて必ず1ページに収める**ので、収まらないときは「07 書き出し」で何行あふれているかを知らせる |
| 奥付 | 最終ページの**地に寄せて**細い罫で切る。縦組みの本でも奥付だけ横組み(紙の本。**電子書籍では奥付も著者紹介も本文と同じ向きで流す**。ページの中に向きの違う箱を作らない)。発行日・追加行(ISBN など)を指定できる。**奥付の背景は［奥付と著者紹介を入れる］でも変えられる**(［背景］のものと同じ設定) |
| 画像の切り分け | Word が EMF/WMF で保存した画像は**ブラウザが描画できない**ので、［挿絵］の一覧のその絵の行と入稿前チェックに形式名を出し、PNG か JPEG に選び直すよう促す |
| プレビュー | Vivliostyle CoreViewer による見開き表示。設定変更の 0.4 秒後に再組版 |
| 電子書籍の下見 | **書き出す EPUB そのもの**(`buildEpubBook`。書き出しと同じ関数で、違うのは画像の参照先だけ)を、Kindle 端末くらい/スマホくらいの枠で1画面ずつめくる(`preview/EbookPreview.tsx`)。1ファイルずつ iframe に XML として読ませ、段組みで画面ごとに区切る。文字の大きさ 小・中・大。紙と電子の両方を作る本は下見の下の［紙の本｜電子書籍］で切り替え、**電子書籍だけの本はいつも電子の下見で、紙の組版は作らない**(帯のサイズ・行送り、ページ一覧、判型、紙だけの入稿前チェックも出さない)。電子を見ているあいだ紙の下見は隠れて組版も止まるので、2つを同時に組むことはない。Chrome で流した一例なので、ストアのプレビューで確かめる断りは残す |
| ページサムネイル | プレビュー横に縦一列。**組み上がりを待たず、出来たページから順に出る**(初出 約1.3秒)。押すとそのページへ飛び、組み直しても見ていたページに留まる |

## 出力の確認方法

- **EPUB**: [epubcheck](https://www.w3.org/publishing/epubcheck/) と Amazon の Kindle Previewer 3 で確認
- **紙PDF(アプリから)**: 印刷ダイアログで「送信先: PDFに保存」「余白: なし」「背景のグラフィック: オン」
- **紙PDF(寸法厳密に検証したいとき)**: CLI 経由のほうが判型が正確(印刷ダイアログ経由は Chromium の丸めで +0.16mm)

  ```bash
  npx tsx scripts/render-sample.ts out.html
  npx @vivliostyle/cli build out.html -o out.pdf --executable-browser "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
  ```

  出来た PDF は PyMuPDF で文字座標まで実測できる(手順は HANDOVER の運用メモ)。
